# Cover LeetCode — 大枠概観 → 手書き定着 の2段階学習

`docs/cover-leetcode-plan.md` の進捗を確認し、次の未完了ステップを進める。
細部の暗記より「議論できる」状態を先に作るのが第1段階の目的。第2段階で自力実装を定着させる。

進捗・復習スケジュールは `docs/cover-leetcode-progress.json` で管理する。

## 手順

### 0. 復習スケジュールの確認

`docs/cover-leetcode-progress.json` を読む。存在しない場合は `{"completions": {}}` で初期化する。

本日の日付と各ステップの `nextReview` を比較し、**復習期日が今日以前のステップ**を抽出する。

#### progress.json の構造

```json
{
  "completions": {
    "1-A-1": {
      "completedAt": "2026-04-30",
      "reviews": [],
      "intervalLevel": 0,
      "nextReview": "2026-05-01"
    }
  }
}
```

#### 間隔反復アルゴリズム

| intervalLevel | 次の復習まで |
|---|---|
| 0 | 1日後 |
| 1 | 3日後 |
| 2 | 7日後 |
| 3 | 14日後 |
| 4 | 30日後 |
| 5 | 卒業（nextReview: null） |

**成功時**: `intervalLevel` を +1。
**失敗時**: `intervalLevel` を `max(0, current - 1)` に戻す。

### 1. 進捗の確認

`docs/cover-leetcode-plan.md` を読み、最初の未完了ステップ（`- [ ]`）を「次のステップ」として特定する。

第1段階（~50ステップ）と第2段階（~70ステップ）の合計~120ステップ。
段階別に進捗を表示する:

```
📊 進捗
  第1段階（議論できる状態）: 5/50 完了 [██░░░░░░░░░░░░░░░░░░] 10%
  第2段階（実装できる状態）: 0/70 未着手
  全体: 5/120 [█░░░░░░░░░░░░░░░░░░░] 4%
```

復習がある場合は `🔔 復習が必要 (N件)` を表示し、最も期日が古いものを優先。

復習がない場合は次の未完了ステップを案内する:

```
👉 次のステップ: 1-A-6 📖 Queue — FIFO、BFS で使う、JS で効率的に作る方法
```

### 2. ステップの種類で対応を分岐

ステップの記号で対応を変える:

- **📖 概念ツアー** → 手順 2-O（概念対話）
- **🔍 解答読解** → 手順 2-R（コード読解対話）
- **⚖️ 解法比較** → 手順 2-C（比較対話）
- **🛠 自力実装** → 手順 2-I（テンプレート生成）
- **🧠 復習** → 手順 2-S（間隔反復出題）

#### 理解度の判定

ユーザーの「OK」だけではステップ完了と判定しない。説明を聞いた後、ユーザーに自分の言葉で説明してもらい、類題や条件変更による応用確認を行う。誤りや曖昧さがあれば補足説明と再質問を行い、理解できていると確信できるまで質問と指導を繰り返す。十分な理解が確認できた場合のみ、ステップ完了として進捗を更新する。

自由記述の負担を抑えるため、確認方法は選択式・穴埋め・計算量の選択・短いキーワード回答・コードの一部修正を優先する。理解の確認に説明が必要な場合も、まず一言や1〜2文で答えられる質問にする。

確認問題に最初に誤答した場合、正しい答えを提示した後の言い直しだけでは合格としない。誤答の原因を説明し、別の例・逆向きの例・条件変更のいずれかで、ユーザーが自力で判断できることを再確認する。確認できるまではステップを完了扱いにせず、誤って完了記録した場合は取り消す。

#### 手順 2-O: 概念ツアー（📖）

ファイルは生成しない。Claude が概念を**少しずつ**提示し、ユーザーと議論する。
1ステップ30分目安。完璧を目指さない。

**進め方の指針**:
- 概念の「正体」「いつ使うか」「主要操作の計算量」「弱点・落とし穴」を順に説明
- 各パートで「ここまで OK?」を確認してから次へ
- 一気に全部説明しない。1パート3〜5文 + コード例1〜2個まで
- ユーザーが「OK」「次へ」と言ったら次のパートへ

**最後のパート完了時**: ディスカッション質問を1〜2個投げて理解度確認:
- 「では、配列で重複検出する場合と Set で重複検出する場合の違いを言葉で説明してみてください」
- 「Tree の DFS と BFS、それぞれどんな問題に向いている？」

ユーザーが答えたらフィードバックして、間違いがあれば補足する。理解できていると確信できるまで、追加質問・類題・条件変更による応用確認と指導を繰り返す。理解が確認できたらステップ完了 → 手順 7（progress.json 更新）。

#### 手順 2-R: 解答読解（🔍）

ファイルは生成しない。Claude が問題と完成コードを提示し、ユーザーに分析させる。

**フォーマット例**:

```
## 🔍 解答読解: Two Sum (#1)

### 問題
配列 nums と整数 target が与えられる。和が target になる2つの要素のインデックスを返す。

### 解答コード
\```javascript
function twoSum(nums, target) {
    const map = new Map();
    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];
        if (map.has(complement)) {
            return [map.get(complement), i];
        }
        map.set(nums[i], i);
    }
}
\```

### 質問
1. このコードの時間計算量は？
2. なぜ Map を使うのか？配列だけで解いたら何が変わる？
3. このアルゴリズムの核心的な発想は何？
```

ユーザーの回答にフィードバック。間違いや見落としを補足する。理解できていると確信できるまで、追加質問・類題・条件変更による応用確認と指導を繰り返す。
最後に「他に気になる点はありますか？OK なら次へ」と案内。

#### 手順 2-I: 自力実装（🛠）

対応するディレクトリにテンプレートファイルを生成する。
ディレクトリ命名: `src/cover/{phase}/{step-id}-{slug}.js`
- 第1段階: `src/cover/phase1/`
- 第2段階: `src/cover/phase2/`

例: `src/cover/phase2/2-G-1-two-sum.js`

**テンプレート**:

```javascript

// =============================================

// =============================================
// 問題: {問題の説明}
// =============================================

    // TODO: ここに実装を書いてください
}

// --- テスト ---
console.assert(/* テスト */, "テスト1 失敗");
console.assert(/* テスト */, "テスト2 失敗");
console.assert(/* テスト */, "テスト3 失敗");

- ファイルパス
- 実行コマンド: `node --watch {ファイルパス}`
- 「TODO 部分を実装したら教えてください」

#### 手順 2-S: 復習（🧠）

復習対象のステップ範囲を plan.md から特定し、過去ステップから新規問題を出題する。

復習タイプの判定:
- **概念系（📖系のステップを復習）** → 概念質問を出す（「Set はいつ Array より使うべきか？」など）
- **読解系（🔍系のステップを復習）** → 新しい問題のコードを提示して計算量を答えさせる
- **実装系（🛠系のステップを復習）** → 新規問題の実装テンプレートを生成

実装系の復習はファイル生成あり: `src/cover/review/review-sr-{ステップID}-r{回数}.js`

### 3. レビュー（自力実装ステップの場合）

ユーザーが「できた」「レビューして」等と言った場合:

1. 該当ファイルを読む
2. `node` で実行してテストが通るか確認
3. 結果に応じて:
   - **失敗** → 失敗内容を表示（ヒントは求められるまで出さない）
   - **通過** → 手順 4（ディスカッションフェーズ）へ

### 4. ディスカッションフェーズ（実装ステップ・テスト通過後）

すぐ完了にせず、コードについて議論する:

1. **コードの改善点**（あれば）
2. **別解の紹介** — 別アプローチでも解けることを示す
3. **計算量の振り返り** — 書いた解の Big O を確認

```
✅ 全テスト通過！

### コードレビュー
（フィードバック）

### 別解
（別アプローチ）

### 計算量
時間: O(n)、空間: O(n)

---
質問はありますか？OK なら次へ進みましょう！
```

ユーザーが「OK」と言ったら手順 5・7 へ。

```
- [x] **1-A-1** 📖 配列 (Array) — ... ✅ 2026-04-30
```

### 6. 段階の節目処理

第1段階最後のステップ（**1-D-14**）が完了した時:
- 「🎉 第1段階完了！議論できる状態になりました」と祝う
- 第1段階を終えた時点での選択肢を提示:
  - 「議論できれば十分」→ ここで卒業して継続的に AI解答を読む
  - 「実装力もつけたい」→ 第2段階に進む

ユーザーの選択を待つ。

第2段階最後のステップ（**2-H-25**）完了時:
- 「🏆 全プラン完了！Medium まで自力で書ける状態になりました」と祝う

### 7. progress.json の更新

#### 通常ステップ完了時

```json
{
  "ステップID": {
    "completedAt": "本日",
    "reviews": [],
    "intervalLevel": 0,
    "nextReview": "本日+1日"
  }
}
```

#### 間隔反復復習の完了時

**成功**: `reviews` に `{ "date": "本日", "passed": true }` 追加、`intervalLevel` +1、新 `nextReview` 計算（Level 5 で `null`）。

**失敗**: `reviews` に `passed: false` 追加、`intervalLevel` を `max(0, current - 1)`、`nextReview` 再計算。

### 8. 完了予測の表示

進捗表示時に予測を表示する:

#### 計算ロジック

1. `progress.json` の最古 `completedAt` から本日までの経過日数（`本日 - 開始日 + 1`）
2. ペース = 完了ステップ数 ÷ 経過日数
3. **第1段階完了予測**: 残り(50 - 第1段階完了数) ÷ ペース 日後
4. **第2段階完了予測**: 残り(120 - 完了数) ÷ ペース 日後
5. **議論力獲得予測**: 第1段階完了予測日（手書きスキップで議論できる状態）
6. **完全卒業予測**: 第2段階完了予測日 + 55日（最終ステップの復習卒業）

#### 表示例

```
📅 議論力獲得予測（第1段階完了）: 2026年8月15日（残り45ステップ / 0.5/日ペース）
🎓 完全卒業予測（第2段階+復習卒業）: 2027年6月10日
```

完了ステップが0の場合は予測を表示しない。
